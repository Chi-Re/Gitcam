# gitcam 部署运维指南

> 适用于第 4 阶段交付的 Docker 化部署（`deploy/docker-compose.prod.yml`）。

## 一、架构

```
浏览器
  │  HTTP :8080
  ▼
web（Nginx 1.27，静态 SPA + 反向代理）
  │  /api/*  /git/* → backend:5000
  ▼
backend（Flask + gunicorn，:5000）
  ├── MySQL 8（:3306 容器内）
  └── MinIO（:9000 容器内）
数据卷：mysql_prod_data / minio_prod_data / repos_prod_data / uploads_prod_data
```

## 二、快速部署

前置：安装 Docker 与 Docker Compose。

```bash
# 一键部署（默认对外端口 8080）
bash scripts/deploy.sh

# 或手动分步（注意：prod 编排在 deploy/ 独立目录，避免与开发 compose 合并）
docker-compose -f deploy/docker-compose.prod.yml up -d --build
```

完成后访问 `http://<服务器IP>:8080`，默认管理员 `admin / admin123`（**首次登录后务必修改**）。

## 三、环境变量（.env 文件，与 compose 同目录）

| 变量 | 说明 | 默认值 |
|---|---|---|
| `SECRET_KEY` / `JWT_SECRET_KEY` | 会话密钥，生产必改 | change-me-in-production |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` | MySQL 密码 | gitcam_root_prod / gitcam_prod |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | MinIO 密钥 | gitcam_minio / gitcam_minio_prod |
| `EXTERNAL_BASE_URL` | 对外访问地址（影响 git clone 提示） | http://127.0.0.1:8080 |
| `MAIL_ENABLED` 等 | 邮件通知（SMTP） | false（仅站内通知） |
| `GUNICORN_WORKERS` | gunicorn worker 数 | 4 |
| `PORT` | 对外端口（deploy.sh） | 8080 |

## 四、常用运维命令

```bash
docker-compose -f deploy/docker-compose.prod.yml ps          # 状态
docker-compose -f deploy/docker-compose.prod.yml logs -f backend   # 后端日志
docker-compose -f deploy/docker-compose.prod.yml logs -f web       # 前端/代理日志
docker-compose -f deploy/docker-compose.prod.yml restart backend   # 重启后端
docker-compose -f deploy/docker-compose.prod.yml down        # 停止（数据保留）
docker-compose -f deploy/docker-compose.prod.yml down -v     # 停止并删除数据卷（慎用）
```

## 五、数据备份与恢复

所有持久数据在 Docker volumes 中：

```bash
# 备份（示例：MySQL 逻辑备份）
docker exec gitcam-prod-mysql mysqldump -ugitcam -p"$MYSQL_PASSWORD" gitcam > gitcam_$(date +%F).sql

# 仓库数据（Git 裸仓库 + 上传文件）
docker run --rm -v dachuangsai_repos_prod_data:/data -v "$PWD":/backup \
  alpine tar czf /backup/repos_$(date +%F).tar.gz -C /data .

# 恢复 MySQL
cat gitcam_xxx.sql | docker exec -i gitcam-prod-mysql mysql -ugitcam -p"$MYSQL_PASSWORD" gitcam
```

建议：每日备份 MySQL 与 repos 卷，保留最近 7 天。

## 六、健康检查与监控

- 各容器配置了 HEALTHCHECK（15s 间隔）；`docker ps` 显示 healthy 即正常。
- 接口健康检查：`curl http://<host>:8080/api/health` → `{"status":"ok"}`
- 后端每请求响应头 `X-Process-Time-MS` 可观察延迟。
- 压测/容量评估：`python3 scripts/benchmark.py --base http://<host>:8080`

## 七、故障排查

| 现象 | 排查 |
|---|---|
| 8080 打不开 | `docker-compose ps` 检查 web 容器；`logs web` 看代理错误 |
| 后端 unhealthy | `logs backend` 查看数据库连接；确认 mysql 容器 healthy（密码错误会报 Access denied） |
| git clone/push 失败 | 确认 `http.receivepack` 已启用（镜像已内置）；检查 `logs backend` 中 `/git/` 请求状态码；私有仓库需成员身份 |
| 推送超大文件超时 | web 容器 `client_max_body_size` 已设 200m，`proxy_read_timeout` 300s；仍超时请检查网络 |
| 忘记管理员密码 | `docker exec -it gitcam-prod-mysql mysql -ugitcam -p gitcam` 后重置：`UPDATE users SET password_hash=...`（可用 backend 容器内 python 生成哈希） |

## 八、生产安全建议

1. 修改默认管理员密码、所有环境变量密钥；
2. 若部署于公网，为 web 配置 HTTPS（Nginx 加证书或前置网关）；
3. 定期更新容器镜像与依赖；
4. 邮件通知需配置真实 SMTP 后启用（`MAIL_ENABLED=true`）。
